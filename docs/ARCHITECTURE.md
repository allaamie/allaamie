# AL LAMEA | اللامع — بنية المنصة (Architecture)

> وثيقة حيّة تصف بنية دار «اللامع» الرقمية كما هي فعلاً في الكود وقاعدة البيانات.
> قاعدة الأمانة: **لا رقم ولا توصية ولا حالة تُعرض إلا من بيانات فعلية** — 🟢 بيانات فعلية · 🟡 توصية بموافقة · 🟠 توقع غير مؤكد.
> شعار الدار الرسمي (`assets/allamea-logo.png`، `allamea-logo-mono.png`، `favicon.png`) **لا يُعاد تصميمه أو تلوينه أو استبداله بأي بديل مولّد** — يُحضَّر عبر `python3 tools/prepare-logo.py <logo.png>`.

## 1) خريطة الوحدات

| الملف | الدور |
|---|---|
| `index.html` + `styles.css` + `script.js` + `catalog.js` | **واجهة المتجر** (عربية RTL): Hero سينمائي، بطاقات منتجات مع Skeleton، نافذة منتج، سلة، دفع، نجاح. الكتالوج يُزامَن حيّاً من جدول `products` مع سقوط آمن لـ `catalog.js`. |
| `studio.html` + `studio.css` + `studio.js` | **AL LAMEA VIRTUAL STUDIO™** — تجربة افتراضية: شخصية رقمية (Gorilla SVG متحرك)، طبقات لبس `wear_category/layer_order`، إطلالات محفوظة، مستشار ذكي. |
| `ai.js` + `ai.css` | **خبير اللامع** (ذكاء العميل): 13 وحدة (بحث لغوي LEX، تنسيق إطلالات، مقارنة، مقاسات، صورة→منتج، تقييمات، تنبيهات، صوت ar-SA، ولاء، تتبع طلبات). يجيب فقط من بيانات المتجر الفعلية. |
| `admin.html` + `admin.css` + `admin.js` | **لوحة الإدارة** (RBAC): المنتجات، الطلبات، الفريق، القيادة الذكية، الذكاء والأتمتة، المراقبة. حارس دخول `profiles.role ∈ (admin, products, orders, staff)`. |
| `ai-admin.js` | **مركز الذكاء والأتمتة (Owner AI)**: طابور موافقات (11 نوع اقتراح)، تسويق، ميرشندايزنغ، عملاء، شحن، ولاء/كوبونات، إعدادات + شاشة تنفيذية + مراقبة وسجلات. |
| `bi.js` | **لوحة مؤشرات الأعمال**: مباشر، قمع، مبيعات (+توقع)، استوديو، منتجات، عملاء (+خريطة Leaflet كسولة)، متروكات، بحث، تقرير (CSV/XLS/JSON/طباعة). |
| `analytics.js` | **طبقة التحليلات**: جلسات/زوار/جهاز/موقع تقريبي، دفعات أحداث، مزوّدون خارجيون اختياريون (GA4/Meta/TikTok/Clarity عبر `ALAMEA_ANALYTICS_CONFIG`)، إشارة `page_perf`. |
| `error-tracker.js` | **التقاط أخطاء العميل** مبكراً في كل صفحة → حدث `client_error` (dedupe، سقف 8/جلسة). يعمل قبل analytics وبدون Supabase SDK (REST مباشر). |
| `pwa.js` + `sw.js` + `manifest.webmanifest` | **التطبيق التقدمي (PWA)**: تسجيل SW، تحديث سلس، لافتة تثبيت ذهبية (مرة/7 أيام)، تلميح iOS، مزامنة طلبات Offline. |
| `supabase/schema.sql` | **مصدر الحقيقة الوحيد لقاعدة البيانات** (انظر §3). يُشغَّل مرة واحدة على مشروع جديد، وإعادة تشغيله آمنة (idempotent). |
| `portal.html / dashboard.*` | بوابة الفريق القديمة — محفوظة للتوافق. |
| `tools/prepare-logo.py` | معالجة الشعار الرسمي الوحيد (Pillow تُثبَّت ذاتياً). |

## 2) الجداول وصلاحيات RLS (اختصار)

| الجدول | القراءة | الكتابة |
|---|---|---|
| `categories` | عام | `admin` |
| `products` | عام (`is_active`) | `admin`/`products` |
| `orders` | فريق العمل فقط (عبر `my_role()`) | إدراج عام من صفحة الدفع؛ تحديث `admin`/`orders` |
| `profiles` | صاحبه + فريق العمل | `admin` يدير الأدوار |
| `events` / `sessions` | فريق العمل | إدراج عام (تحليلات) |
| `reviews` | عام | إدراج عام (مع approval من الإدارة) |
| `audit_log` | `admin` فقط | فريق العمل يُدرج |
| `ai_tasks` (AI Admin) | فريق العمل | فريق العمل (أرشفة قرارات الاقتراحات) |
| `store_settings` | **عام (قراءة فعلية للعملاء)** | `admin` فقط — مفاتيح: `shipping`، `loyalty`، `locale` |
| `coupons` | محجوبة عن العام (بحماية الخصومات) | `admin`/`products` — العام يقرأها فقط عبر RPC |

**RPC عامة (security definer، تنفيذ مقيد بـ anon/authenticated):**
- `order_status(p_phone)` — حالة طلبات العميل (يستخدمه خبير اللامع والولاء).
- `coupon_peek(p_code)` — يعيد نسبة الخصم `pct` أو `null` **دون كشف قائمة الكوبونات** (فحص فوري في الدفع).
- `coupon_redeem(p_code)` — تحديث ذرّي `uses+1` بشروط الصلاحية داخل `UPDATE` واحد؛ يرجع `pct` وإلا `null` (يُستدعى لحظة تأكيد الطلب فقط — لحظة الحقيقة الوحيدة).

## 3) مخطط الأحداث (Events Catalog)

| النوع | المنطلق |
|---|---|
| `store_visit` / `studio_enter` | analytics.js عند الدخول (مع `returning`) |
| `product_view`، `color_change`، `cart_add`، `checkout_start`، `order_complete` (يدعم `offline`)، `purchase`، `coupon_use`، `newsletter_signup` | script.js |
| أحداث الاستوديو/الذكاء `studio_*`، `ai_search/ai_chat/ai_compare/ai_size/ai_voice/ai_notif/ai_loyalty`، `review_add` | studio.js / ai.js |
| `client_error` | error-tracker.js (رسالة+صفحة+stack مقتطع) |
| `page_perf` | analytics.js — مرة لكل جلسة: `ttfb/dom/load/mem/dpr` (تغذي مراقبة الأداء p95) |
| بحث: `meta { q, results, converted }` | نجاحات تحويل البحث في BI |

كل الأنواع معرّفة بملصقات عربية في `EV_LABEL` داخل `bi.js`.

## 4) الذكاء الاصطناعي ثلاثي الطبقات

1. **ذكاء العميل — خبير اللامع (`ai.js`)**: يوصي وينسّق ويحسب مقاساً ويطابق صوراً ويتتبع طلباً ويجيب عن سياسات الدار ونقاط الولاء — كله من `products/orders/reviews/store_settings` الفعلية؛ لا يخترع منتجاً ولا سعراً.
2. **ذكاء المالك — AI Automation Center (`ai-admin.js`)**: يولّد اقتراحات مسببة (إعادة تخزين، تسعير، وصف/عنوان/وسوم، صور، تصنيف، حمَلات «تُشترى معاً»، وسحب/إبراز منتجات) مرتبة بالأثر.
   **⚠ القاعدة الذهبية: لا يُنفَّذ أي إجراء يؤثر على الأسعار أو المنتجات أو المحتوى إلا بعد موافقة المسؤول صراحة** (نافذة تأكيد) ثم يُوثَّق في `audit_log` ويُؤرشف في `ai_tasks`.
3. **ذكاء القراءة — BI (`bi.js`)**: تحليلات وتوقعات مُعلَّمة بصراحة (فعلي 🟢 / توقع 🟠).

## 5) PWA والعمل دون اتصال (Offline)

- `sw.js` (إصدار `allamea-v20260731-3`): Precache للصفحات/الأصول + SWR للزيارات + **BYPASS** لمصادقة/تحليلات/خرائط/Supabase (شبكة فقط).
- `sync-orders` Background Sync: الطلب الذي فشل إرساله (انقطاع شبكة) يُخزَّن في `localStorage(allamea-offline-orders)` — بحد أقصى 20 — ويُعاد إرساله تلقائياً عند: عودة الاتصال، رسالة `FLUSH_ORDERS` من SW، أو إقلاع الصفحة. شاشة النجاح تصارح العميل: «حُفظ طلبك وسيُرسل عند عودة الاتصال».
- الشحن: `orders.shipped_at/delivered_at` تُختم تلقائياً عند تغيير الحالة من لوحة الإدارة → Shipping Intelligence يحسب متوسط أيام التسليم الفعلي، المعلّقة >5 أيام، المدن، وأداء شركات الشحن (`orders.carrier`).

## 6) الأداء والوصول والمراقبة

- **أداء**: حركات بـ `transform/opacity` فقط (60FPS)، Lazy-loading للصور وLeaflet، تحميل كسول لوحدات BI/AI-Admin (`import()`)، طبقة تحليلات بدفعات (flush 3.5s / ≥12 حدثاً / pagehide)، كاش محدود 90 أصلاً مع trim.
- **وصول (A11y)**: `dir=rtl` + `lang=ar`، تباين ذهبي/عاجي على داكن، `:focus-visible` ذهبي واضح، `aria-live="polite"` لمناطق التحديث (المنتجات، #view)، `role=dialog/switch/tablist` للعناصر، تنقّل كامل عن طريق لوحة المفاتيح، نمط فاتح/داكن.
- **مراقبة**: صفحة «المراقبة» (state) تعرض اتصال قاعدة البيانات (زمن Ping فعلي)، أحداث 24س، أخطاء مجمعة بالرسالة مع ردود (resolve محلي)، أداء الصفحات من `page_perf` (avg + p95، وهدف < 3500ms)، وسجل `audit_log`.

## 7) قائمة نشر (Deployment Checklist)

1. **قاعدة البيانات**: شغّل `supabase/schema.sql` كاملاً مرة واحدة في SQL Editor (يضيف `ai_tasks, store_settings, coupons, RPCs, أعمدة orders`). إعادة التشغيل آمنة.
2. **الشعار**: أعد إرفاق الشعار الرسمي ثم `python3 tools/prepare-logo.py <logo.png>` (يولّد الثلاثة بلا تعديلٍ للتصميم).
3. **التحليلات الخارجية (اختياري)**: ضع المفاتيح في كتل `ALAMEA_ANALYTICS_CONFIG` في `index.html`/`studio.html` — لا تعديل للكود.
4. **أدوار الفريق**: عيّن `profiles.role` لكل موظف (`admin` يدير كل شيء، `products` للمنتجات والخصومات، `orders` للطلبات).
5. **الإدارة**: من «الإعدادات» فعّل الشحن/الولاء — تظهر فوراً للعملاء (الولاء وحقل الكوبون لا يظهران للعملاء إلا بعد تفعيلها فعلياً — لا وعود زائفة).
6. راقب «المراقبة» خلال الساعات الأولى (أخطاء + p95).

## 8) لإضافة مزوّد/صفحة/قسم جديد

- **مزوّد تحليلات**: `window.ALAMEA_PROVIDERS.myProvider = { init(id){}, event({name,params}){} }` — يستقبل كل الأحداث تلقائياً.
- **صفحة إدارية**: أضف `data-page` في `admin.html` وعنواناً في `ROUTES`/`TITLES` داخل `admin.js` ثم دالة الرسم؛ للبطاقات استخدم نفس نظام التوكنز (`--gold, --veil, --r, --ease`).
- **اقتراح أتمتة جديد**: أضف حالته في `computeProposals()` بمفتاح فريد `key` ثابت، نوع في `KIND_L`، وفعل `OPS.*` + `audit()` — وسيظهر في طابور الموافقات بموافقة المسؤول فقط.
